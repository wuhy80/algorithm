# 中位数的中位数 Median of Medians

> 用五元组中位数构造确定性选择枢轴

## 先抓住一句话

**中位数的中位数 Median of Medians** 属于确定性选择算法。它用五元组中位数构造质量有保证的枢轴，在最坏线性时间内找到第 k 小元素。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

Quickselect 的效率取决于枢轴能否持续排除足够多元素。随机枢轴只有期望保证；中位数的中位数通过确定性分组保证每轮都能排除固定比例的候选。

五元组不是为了精确找到全局中位数，而是为了低成本得到一个不会过分偏斜的枢轴。

## 心智模型

把数组分成五个一组，取每组中位数，再递归选择这些中位数的中位数。这个枢轴两侧都能保证存在足够多元素。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 第 k 小元素始终位于当前候选区间；三路分区后只递归包含目标秩的一侧，并按被排除元素数调整 k。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **中位数的中位数 Median of Medians** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 小数组直接排序并返回第 k 小元素。
2. 每五个元素一组排序，收集各组中位数。
3. 递归求中位数集合的中位数，把它作为当前枢轴。
4. 按小于、等于、大于枢轴三路分区，只递归目标秩所在部分。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
select(values, k):
    if values.size <= 5: return sorted(values)[k]
    medians = [median(group) for each group of at most 5]
    pivot = select(medians, medians.size / 2)
    (low, equal, high) = partition(values, pivot)
    if k < low.size: return select(low, k)
    if k < low.size + equal.size: return pivot
    return select(high, k - low.size - equal.size)
```

## 复杂度怎么分析

**结论：最坏时间 O(n)，额外空间取决于实现**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 把“中位数集合的中位数”误当成原数组的精确中位数。
- 分组尾部不足五个元素时直接丢弃，破坏候选集合。
- 递归右分区时没有扣除左分区和等值分区的大小。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：需要确定性最坏 O(n) 选择，或输入可能专门针对固定/随机枢轴构造的场景。

不适合：普通工程数据且更看重常数因子；随机 Quickselect 通常更短、更快。

## 实现判定细节

- 把元素每 5 个分组并取组内中位数，再递归选择这些中位数的中位数作为枢轴；最后不足 5 个的一组也必须参与。
- 三路分区 `< pivot`、`== pivot`、`> pivot` 能正确处理重复值，并让目标秩直接落入等值区间时结束。
- 五元组枢轴保证每轮至少排除常数比例元素，由递推式 `T(n) <= T(n/5)+T(7n/10)+O(n)` 得到最坏 O(n)。
- 要先统一第 k 小使用 0 基还是 1 基，递归进入右区间时同步减去左区和等值区的长度。
