# 字符串滚动哈希 Rolling Hash

> 预处理前缀哈希和幂，常数时间提取任意子串指纹

## 先抓住一句话

**字符串滚动哈希 Rolling Hash** 把字符串前缀编码成多项式哈希，配合 base 的幂在 O(1) 时间提取任意半开区间的子串指纹。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

重复逐字符比较子串会让查询成本随子串长度增长。前缀哈希像前缀和一样，通过两个前缀值相减消去区间外字符。

哈希是概率性指纹，不是字符串本身；需要按风险选择双哈希或原文校验。

## 心智模型

用递推 `H[i+1]=H[i]*base+code(s[i])` 编码前缀。提取 `[l,r)` 时，把 `H[l]` 乘 `base^(r-l)` 对齐后从 `H[r]` 中减去。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> `H[i]` 始终是前 i 个字符的多项式哈希，`power[k]` 始终等于 `base^k mod modulus`；区间公式对相同长度子串使用相同位权。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **字符串滚动哈希 Rolling Hash** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 选择 base、模数和稳定的字符编码。
2. 从左到右构造前缀哈希数组 `H`。
3. 同步预处理 `power[k]=base^k mod modulus`。
4. 用 `H[r]-H[l]*power[r-l]` 提取 `[l,r)`，并把结果规范化到模数范围。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
H[0] = 0
power[0] = 1
for i in 0 .. n - 1:
    H[i + 1] = (H[i] * base + code(s[i])) mod modulus
    power[i + 1] = power[i] * base mod modulus

substring_hash(l, r):
    return normalize(H[r] - H[l] * power[r - l], modulus)
```

把伪代码映射到本目录的 `app.js` 时，可以按“解析输入 → 初始化状态 → 生成每一步 → 更新指标 → Canvas 绘制”的顺序阅读。算法逻辑负责决定状态，绘图逻辑只负责把状态呈现出来，两者不要混在一起理解。

## 复杂度怎么分析

**结论：预处理 O(n)，子串哈希 O(1)**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 混用闭区间与半开区间，导致长度和幂次相差一。
- 取模减法没有规范化负值，或乘法类型溢出。
- 把单哈希相等当作绝对相等，忽略碰撞概率和对抗性输入。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：大量子串相等查询、重复检测，以及配合二分查找求最长公共前缀。

不适合：必须零碰撞的安全校验，或字符串频繁修改但没有动态哈希结构的场景。
