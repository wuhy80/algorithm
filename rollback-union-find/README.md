# 可回滚并查集 Rollback DSU

> 记录每次合并修改，通过快照按相反顺序恢复父节点与集合大小。

## 先抓住一句话

**可回滚并查集 Rollback DSU** 属于可撤销数据结构。它在普通并查集之外记录每次合并修改，使状态能够恢复到任意已保存的历史深度。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

分治和时间线段树会进入一个区间、临时加入若干关系，再返回父区间。若每次返回都重建并查集，代价过高；记录修改即可按相反顺序撤销。

回滚依赖“修改可完整重放”的对称性：合并前把即将覆盖的旧值写入历史栈，快照保存栈长度，退出分支时逆序恢复到该长度。为限制每次合并的修改数量，查找根节点不能使用路径压缩。

## 心智模型

把历史栈看成事务日志。快照只需记录当前栈长度；回滚时逐项恢复父节点、集合大小和分量数，直到历史栈回到该长度。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 每次 `union` 在历史栈中留下足以完全撤销本次操作的记录；回滚到快照后，并查集状态必须与创建快照时逐项一致。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **可回滚并查集 Rollback DSU** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 使用按大小合并维护父指针树，但不执行路径压缩。
2. 合并两个不同根前，记录被挂接的根、接收根及其旧大小。
3. 创建快照时保存历史栈长度；无效合并也要保持操作计数语义一致。
4. 回滚时弹出历史记录，按逆序恢复父节点、大小和分量数。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
snapshot(): return history.size

union(a, b):
    a, b = find(a), find(b)
    if a == b: history.push(NO_CHANGE); return
    if size[a] < size[b]: swap(a, b)
    history.push((b, size[a]))
    parent[b] = a
    size[a] += size[b]

rollback(target):
    while history.size > target:
        restore the last recorded change
```

把伪代码映射到本目录的 `app.js` 时，可以按“解析输入 → 初始化状态 → 生成每一步 → 更新指标 → Canvas 绘制”的顺序阅读。算法逻辑负责决定状态，绘图逻辑只负责把状态呈现出来，两者不要混在一起理解。

## 复杂度怎么分析

**结论：O(log n) 合并 / O(1) 单步回滚**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 直接使用路径压缩，却没有记录它修改的所有父指针，导致无法完整回滚。
- 只恢复被挂接根的父指针，忘记恢复接收根的集合大小或全局分量数。
- 无效合并与有效合并的历史记录规则不一致，导致按操作数回滚时错位。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：离线动态连通性、分治搜索，以及需要“进入分支后修改、退出分支时恢复”的合并查询。

不适合：要求路径压缩级别常数性能的普通在线合并，或无法预知操作、需要任意在线删除边的场景。

## 实现判定细节

- 每次成功合并只修改“小根的父指针”和“大根的大小”，把旧值压入历史栈；未发生合并也要记录哨兵，才能保持操作与回滚次数对齐。
- 快照就是历史栈长度，回滚到快照时持续弹栈并按相反顺序恢复字段。
- 为了让一次合并只产生 O(1) 个可撤销修改，查找根节点不能做路径压缩；按大小合并保证最坏 O(log n) 查找。
- 回滚恢复的是数据结构状态，不会自动撤销调用方维护的答案计数，额外聚合量也必须进入同一历史记录。
