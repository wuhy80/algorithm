# 欧拉路径 Eulerian Path

> Hierholzer 栈沿未使用边深入并在回退时构造完整路径

## 先抓住一句话

**欧拉路径 Eulerian Path** 属于按边遍历问题。Hierholzer 算法让每条边恰好使用一次，并在回退时拼出欧拉路径或欧拉回路。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

普通 DFS 用 `visited` 标记顶点，会漏掉需要多次经过同一顶点的合法欧拉路径。这里必须标记边，并利用已走完的闭合回路进行拼接。

只有当栈顶顶点再无未使用边时，它在最终路径中的后继关系才确定，因此答案按回退顺序生成后需要反转。

## 心智模型

栈保存当前尚未封闭的行走轨迹；遇到未使用边就继续深入，无边可走才把顶点移入最终序列。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 每条逻辑边最多被取出一次；当顶点从栈中弹出时，它的所有关联可用边已经耗尽，弹出序列的逆序构成最终欧拉路径。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **欧拉路径 Eulerian Path** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 检查度数与连通性条件，并选择合法起点。
2. 把起点压栈；为每条逻辑边维护唯一编号和使用状态。
3. 栈顶仍有未使用边时，标记该边并把另一端压栈。
4. 栈顶无边可用时弹出并追加到答案；最后反转答案。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
stack = [start]
path = []
while stack not empty:
    u = stack.top()
    if u has an unused edge (u, v):
        mark that edge used
        stack.push(v)
    else:
        path.append(stack.pop())
reverse(path)
```

把伪代码映射到本目录的 `app.js` 时，可以按“解析输入 → 初始化状态 → 生成每一步 → 更新指标 → Canvas 绘制”的顺序阅读。算法逻辑负责决定状态，绘图逻辑只负责把状态呈现出来，两者不要混在一起理解。

## 复杂度怎么分析

**结论：Hierholzer 算法时间 O(V+E)，空间 O(V+E)。**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 按顶点标记 visited，错误禁止合法路径重复经过顶点。
- 无向边的两个邻接项没有共享同一个边编号，导致同一条边使用两次。
- 没有先检查奇度数/入出度和非零度顶点连通性，输出不完整路径。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：需要恰好使用每条边一次的路线规划、拼接和欧拉回路问题。

不适合：要求每个顶点只访问一次的哈密顿路径，或目标是最短、最低费用路线的问题。

## 实现判定细节

- 无向图存在欧拉回路要求所有非孤立点度数为偶数；欧拉路径恰有 0 或 2 个奇度点，并且所有非孤立点连通。
- 有向图还要检查入度与出度差：起点为 `out-in=1`，终点为 `in-out=1`，其他点相等；回路则全部相等。
- Hierholzer 算法在“无边可走时”把节点加入答案，因此最终序列需要反转；边必须按编号标记，不能只标记端点。
- 最终路径包含的边数必须恰好等于原图边数，否则即使度数条件成立，也说明非孤立部分不连通。
