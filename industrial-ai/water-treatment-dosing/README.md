# 自来水厂混凝剂加药预测 Water Treatment Dosing

根据原水浊度、处理流量、pH、水温和目标出水浊度，估计混凝剂推荐投加量、小时药耗与预测区间。这个演示解决的不是“让模型直接控制泵”，而是把影响剂量的因素拆开，让工艺人员看懂模型为什么给出这个建议。

## 先抓住一句话

加药预测的核心，是先回答“这批水大约需要多少 mg/L”，再回答“当前流量下每小时要准备多少 kg 药剂”；浓度与总药耗不能混为一谈。

## 为什么需要它

固定剂量无法适应暴雨、换季、上游排水和取水口切换。投少了，絮体形成不足，沉淀池出水浊度上升；投多了，不仅增加药耗，还可能造成余铝、污泥量和 pH 波动。传统做法依靠经验表和烧杯试验，可靠但响应慢。预测模型适合把实时传感器和历史工艺经验整理成“候选剂量”，帮助值班人员更早做试验和调整。

## 心智模型

先把问题拆成四层：

1. **浊度基准**：悬浮颗粒负荷越高，基准剂量通常越大，但不应简单线性增长。
2. **工况修正**：pH 偏离适宜区间、低温导致碰撞和絮凝变慢，都可能需要提高剂量。
3. **质量目标**：目标出水越严格，模型给出的安全余量越大。
4. **产能换算**：推荐浓度乘以流量，得到单位时间药耗。

演示使用平方根函数描述浊度与剂量的边际递减关系，再乘三个可解释修正因子。它不是通用水厂公式，而是一个可以被本厂数据替换的透明骨架。

## 核心不变量

- 在其他条件不变时，原水浊度升高，推荐剂量不应下降。
- 只改变处理流量时，`mg/L` 推荐浓度保持不变，`kg/h` 总药耗随流量同比变化。
- pH 偏离参考点 7.2 越远，风险和不确定性不能变小。
- 低温会扩大修正量和预测区间，提醒系统需要更多现场确认。
- 模型输出永远受工艺上下限约束，不能产生负剂量或无限剂量。

这些不变量比某一组系数更重要。训练梯度提升树、神经网络或时序基础模型以后，也应该用单调约束、边界测试和反事实样本检查它们。

## 算法步骤

1. 校验浊度、流量、pH、温度和目标值是否在模型支持范围内。
2. 用 `5.5 + 2.25 × sqrt(浊度)` 计算透明基准剂量。
3. 计算 pH、温度和目标出水浊度三个修正因子。
4. 将基准剂量与修正因子相乘，并裁剪到 `3~70 mg/L`。
5. 根据偏离参考工况的程度估计不确定性，生成推荐区间。
6. 用 `剂量 × 流量 / 1000` 换算干药耗量 `kg/h`。
7. 根据 pH、剂量和置信度给出“复核”“烧杯试验”或“确认后下发”的流程建议。

## 框架伪代码

```text
base = 5.5 + 2.25 * sqrt(raw_turbidity)
ph_factor = 1 + deviation_from_7_2
temperature_factor = 1 + cold_water_correction
target_factor = 1 + outlet_target_correction

dose = clamp(base * ph_factor * temperature_factor * target_factor, 3, 70)
uncertainty = estimate_operating_distance(ph, temperature, turbidity)
interval = [dose * (1 - uncertainty), dose * (1 + uncertainty)]
chemical_kg_hour = dose * flow_m3_hour / 1000
```

## 跟着演示手算

默认原水浊度为 `35 NTU`，浊度基准约为 `5.5 + 2.25 × sqrt(35) = 18.8 mg/L`。pH 恰好为 7.2，因此 pH 修正为 0；水温 14°C 比参考温度低 1°C，剂量上调约 1.6%；目标出水为 1.0 NTU，不再追加目标修正。最后推荐值约为 `19.1 mg/L`。

当流量为 `1800 m³/h` 时，干药耗为 `19.1 × 1800 / 1000 ≈ 34.4 kg/h`。把流量提高到 `3600 m³/h`，推荐浓度仍约为 `19.1 mg/L`，但小时药耗翻倍。这就是浓度预测与泵送能力计算的边界。

## 动画怎么看

上方加药机器人按照“推荐剂量 × 执行比例”连续滴加，机械臂、药剂管和喷嘴对应实际控制链路；下方罐体从左到右展示原水进入、快速混合、絮凝沉降和出水。深色小颗粒代表原水悬浮物，聚集后下沉的较大颗粒代表絮体，底部颜色加深表示沉降层积累。

把机器人执行比例调到 60%~80%，会看到絮体不足、残余颗粒增加和模拟出水浊度升高；调到 100% 附近，池内显示稳定絮凝；超过 120% 则进入投加偏高状态。这里的水体变化是帮助理解闭环控制的示意动画，不是计算流体力学或真实混凝动力学仿真。

## 复杂度怎么分析

单次预测只执行固定数量的算术运算，时间复杂度为 `O(1)`，额外空间复杂度为 `O(1)`。页面为了绘制完整响应曲线，会在 61 个浊度采样点重复计算，因此仍可视为固定成本；如果扩展为长度为 `n` 的历史窗口模型，特征提取通常是 `O(n)`。

## 常见错误

- **把流量直接乘进推荐浓度**：流量决定总量，不应无依据地改变同一水质下的 mg/L。
- **只看浊度**：相同浊度下，天然有机物、藻类、碱度和颗粒表面性质可能完全不同。
- **随机切分训练集**：同一天相邻样本高度相似，会造成严重时序泄漏。
- **只优化平均误差**：高浊度突变样本少但风险大，应单独评估 P90 误差和超限率。
- **把预测值直接下发 PLC**：缺少工艺边界、泵能力、余铝和人工审批时，自动控制不可接受。
- **把执行值等同于推荐值**：泵频、冲程、药液浓度和设备标定误差都会让实际投加偏离模型建议，需要流量计或称重反馈闭环。
- **忽略药剂有效含量**：`kg/h` 是干药口径，实际溶液泵频还要结合浓度、密度和标定曲线。

## 什么时候使用

适合用于日常工况的剂量建议、烧杯试验起点、暴雨来水预警、药剂采购估算和模型教学。不适合在传感器故障、取水源突然切换、藻类暴发、pH 超范围或缺少本厂校准数据时直接使用。

## 与工业大模型的联系

生产版本可以把分钟级时序交给 TCN、Temporal Fusion Transformer、PatchTST 或时序基础模型，同时读取工艺日志和天气信息。树模型往往是很强的第一版，因为它能处理非线性、缺失值和特征交互；时序模型则更适合识别暴雨前后的变化速度与滞后关系。

真正有价值的“工业大模型”不是参数更多，而是同时输出剂量区间、出水浊度、余铝、药耗和风险解释，并能引用烧杯试验、操作规程与历史相似工况。最终下发仍应经过规则引擎、PLC 上下限和人员权限控制。

## 自测问题

2. 如果 pH 偏离适宜区间，为什么置信度应下降？
3. 训练数据怎样切分才能避免同一场降雨的信息泄漏？
4. 为什么平均绝对误差很低，仍可能在高浊度场景发生危险？
5. 从干药 `kg/h` 换算成溶液泵频还缺少哪些参数？
