# 多传感器异常检测

## 这个演示解决什么问题？

工业设备会持续产生振动、温度、电流和压力等时间序列。真正危险的信号通常不是一个固定的绝对值，而是“相对于最近工况突然偏离”：夜班低负载时温度 70℃ 可能正常，负载不变时突然升到 70℃ 则值得检查。本实验用一组可重复的合成振动和温度数据，演示如何把这种偏离变成可解释的告警分数。

页面中的模型是生产系统的透明基线，不是声称可以直接替代设备安全联锁的工业大模型。它适合用来理解窗口、阈值、噪声和误报之间的关系。

## 交互方式

- **滚动窗口**：每个采样点只和最近 `N` 个点比较。窗口越短，变化响应越快但更容易把噪声当异常；窗口越长，分数更稳定却可能错过工况切换。
- **z-score 阈值**：分数超过阈值才画出告警点。阈值低会提高召回率，也会增加需要人工确认的告警。
- **异常强度**：放大合成数据中的冲击和温升，观察同一检测策略对故障迹象的响应。

## 算法步骤

设传感器序列为 `x`，对时间 `t` 的窗口 `W_t` 计算：

```text
μ_t = mean(W_t)
σ_t = std(W_t)
z_t = |x_t - μ_t| / (σ_t + ε)
```

振动和温度各自得到 z-score 后，在同一时刻取较大值：`score_t = max(z_vibration, z_temperature)`。这样不需要把摄氏度和 g 直接相加，也不会因为量纲不同而偏向某个传感器。`ε` 用来处理窗口内几乎恒定的信号。

## 为什么需要更高级的模型？

滚动 z-score 假设窗口内的数据近似同分布，无法理解长周期季节性、负载上下文或多个传感器之间的关联。上线时可以按难度逐步升级：

1. 用 EWMA、CUSUM 或变点检测处理缓慢漂移；
2. 用 Isolation Forest、One-Class SVM 或自编码器学习多变量的正常区域；
3. 用 TCN、时序 Transformer 或 PatchTST 编码更长的工况窗口，再用重构误差或预测残差检测异常；
4. 用带工单和维修结果的工业时序基础模型，联合输出异常类型、影响范围和剩余寿命。

无论使用哪种网络，都应保留预测区间、模型版本、数据漂移监测和告警审计。告警去重、冷却时间、同一设备的多点确认，以及“必须人工确认后才能停机”的安全策略，往往比再堆一层网络更重要。

## 复杂度与常见错误

直接实现中，每个点都扫描窗口，时间复杂度为 `O(T × W)`，空间复杂度为 `O(T)`（保存分数）。生产实现可以用前缀和与平方和把均值、方差更新降到 `O(T)`，或者使用流式统计避免保存全部历史。

常见错误包括：

- 把未来数据放进窗口，造成时间泄漏；
- 用全历史均值掩盖工况变化；
- 在训练前后改变传感器标定或缺失值处理方式；
- 只看单点告警，不看持续时间、设备状态和维修反馈；
- 让异常检测结果直接触发高风险动作，却没有人工审批和回滚路径。
