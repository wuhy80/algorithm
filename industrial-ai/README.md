# 工业大模型实验室

工业现场的数据不是“把一段文本丢给聊天模型”这么简单。设备状态通常由高频传感器、低频工艺参数、班次和环境上下文共同决定；维护记录又以工单、检修备注和备件信息的形式存在。一个可落地的工业大模型专题，应该把这些异构信号统一成可追溯的状态，再把预测转换为有人确认、可以审计的动作。

## 专题目标

本专题围绕四个常见工业任务建立独立演示：剩余使用寿命（RUL）预测、产量预测、异常检测和维护决策。每个目录均保留自己的 `index.html`、`styles.css`、`app.js`、`README.md` 与 `solution.py`，可以单独打开、阅读和扩展。

## 任务地图

| 任务 | 输入 | 输出 | 工业价值 |
| --- | --- | --- | --- |
| [剩余使用寿命](remaining-useful-life/) | 温度、振动、电流的退化窗口 | 剩余时间、风险等级、置信度 | 提前安排检修与备件 |
| [产量预测](yield-forecast/) | 历史产量、班次、计划停机 | 未来产量与目标缺口 | 排产、交付和能源调度 |
| [异常检测](anomaly-detection/) | 多变量传感器与上下文 | 异常点、残差、告警等级 | 减少误报并发现早期故障 |
| [维护决策](maintenance-decision/) | 故障概率、成本和约束 | 动作与期望成本 | 把预测转成可执行方案 |

## 从透明基线升级到大模型

浏览器演示故意使用线性退化、滑动统计、季节基线和期望成本等可解释算法。它们不是对生产系统效果的承诺，而是帮助学习者看清数据、状态和决策之间的关系。生产系统可以按以下路径升级：

1. **时序编码**：用 TCN、PatchTST、Temporal Fusion Transformer 或时序基础模型编码多尺度窗口，并加入工艺、班次、环境等协变量。
2. **多任务预测**：共享状态表示，同时预测 RUL、未来产量、良率和异常概率，减少不同模型之间的状态漂移。
3. **不确定性与校准**：输出分位数、预测区间或 conformal prediction 覆盖率，不把单个点预测当作事实。
4. **知识与行动**：把设备手册、工单和维修规程建立检索索引，由维护助手解释“为什么告警”和“下一步依据哪条规程”，最终动作仍需要权限和人工确认。

## 工业落地时必须补齐的治理

- 按设备、产线和工况切分训练/验证，避免同一设备的未来信息泄露到训练集。
- 记录传感器版本、缺失值处理、模型版本、预测时间和人工处置结果，保证预测可回放。
- 分离“预测故障概率”和“是否停机”的责任边界，使用成本函数与安全规则约束自动动作。
- 监测数据漂移、概念漂移和校准误差；当置信度下降时降级到规则或人工流程。

## 运行

直接打开 [专题首页](https://wuhy80.github.io/algorithm/industrial-ai/)，再进入四个独立实验。每个实验都支持调整参数，图表会立即重新计算，底部 README 给出状态定义、复杂度、限制和进一步升级方向。
