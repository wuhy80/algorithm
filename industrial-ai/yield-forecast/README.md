# 产量与交付预测 Yield Forecast

> 产线在给定工况、班次和计划停机下，未来还能稳定交付多少？

## 先抓住问题

产量预测不是把历史曲线向右平移。工厂真正关心的是：在已知班次节奏、计划停机和工艺约束下，未来每个班次能产出多少，以及目标缺口是否会扩大。这个预测服务于排产、物料准备和交付承诺；需求预测则回答市场需要多少，两者不能混为一谈。

## 演示做了什么

页面使用一条可复现的合成产线序列：长期趋势叠加班次季节性与小幅噪声。模型只读取最近 18 个班次，用最小二乘直线估计趋势，再把未来班次的季节项叠加到趋势上。计划停机作为外生变量进入可用率修正：

```text
availability = max(0, 1 - planned_downtime_hours / (horizon * 8))
forecast[t] = (level + slope * t + seasonal[t]) * availability
```

拖动“计划停机时长”“目标产量 / 班”和“预测步数”，图表会同步更新历史产量、预测产量、目标线和停机影响区间。预测平均产量与目标的差值是排产提示，不是质量放行结论。

## 为什么需要时间窗口

窗口太短，趋势会被单个班次的异常放大；窗口太长，又会把换线、设备老化或季节变化抹平。生产系统通常按设备、产品和工况分组选择窗口，并用滚动回测检查不同窗口的误差。演示固定为 18 个班次，是为了让“窗口—趋势—外推”的关系清晰可见。

## 不变量与边界

1. 预测时只能使用当前时刻及之前的观测，不能把未来实际产量泄漏进窗口。
2. 计划停机只能降低可用产能，不应凭空提高产量；可用率被限制在 `[0, 1]`。
3. 预测产量不能为负数，目标缺口的符号约定为“预测减目标”。
4. 置信度是残差与停机不确定性的教学指标，生产环境必须用按设备切分的验证集校准预测区间。

## 从基线升级到工业大模型

- **特征层**：加入订单、产品配方、换线时间、良率、环境、班次和维护工单等外生变量。
- **模型层**：用 TCN、Temporal Fusion Transformer（TFT）或 PatchTST 学习长短期依赖；多品种产线可采用共享编码器加产品条件向量。
- **输出层**：预测 P10/P50/P90 分位数或完整概率分布，向计划员展示交付风险，而不是只给一个点估计。
- **治理层**：监测概念漂移和缺失传感器，记录模型版本、输入快照、人工覆盖和回滚结果；安全约束优先于模型推荐。

## 常见错误

- 把需求预测的结果直接当成产能预测，忽略设备可用率与良率。
- 随机切分时间序列训练集，导致未来信息泄漏；应按时间滚动验证。
- 只看平均绝对误差，不看高峰交付周的欠产风险和预测区间覆盖率。
- 把停机时长当成唯一因果变量，没有区分计划停机、故障停机和换线损失。
- 模型预测低于目标就自动改排产，没有经过质量、库存和安全审批。

## 复杂度

令窗口长度为 `W`、预测步数为 `H`。线性趋势估计为 `O(W)` 时间、`O(W)` 空间，生成预测为 `O(H)` 时间；演示在浏览器 Canvas 上绘图还需 `O(W + H)`。TCN/Transformer 的推理复杂度则取决于层数、隐藏维度和上下文长度，不能用这个基线的复杂度代替。

## 自测问题

1. 当计划停机从 0 增加到 32 小时，为什么预测会下降但历史曲线不变？
2. 如果最近 18 个班次刚好处于换线期，如何改造窗口或特征才能避免趋势误判？
3. 为什么生产计划更需要 P90 欠产风险，而不是只看平均预测？
