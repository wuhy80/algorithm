# 剩余使用寿命预测 Remaining Useful Life

> 从设备状态退化轨迹估计距离安全阈值还有多少时间。

## 先抓住一句话

RUL 不是“预测一个日期”，而是预测健康状态何时穿过业务定义的失效阈值。演示把最近窗口的健康度拟合为一条退化斜率，计算阈值交点；生产模型则会用多传感器时序编码器学习非线性退化。

## 为什么需要它

只看当前温度或振动值，无法区分短时波动和持续退化。RUL 将状态、趋势、工况和历史维护信息放在同一时间轴上，帮助安排备件、检修窗口和安全降载。

## 心智模型

设健康度为 h(t)，安全阈值为 h_safe。当前窗口给出退化斜率 k，最简单的预测是 h(t+q)=h(t)+kq。当 k<0 且预测轨迹穿过阈值时，q 就是剩余步数。真正的工业模型还要输出区间而非单点。

## 核心不变量

每次预测都只能使用预测时刻之前的数据；退化窗口的时间顺序不能被打乱；安全阈值必须来自设备或工艺约束，而不是为了让曲线好看而临时选择。

## 算法步骤

1. 对齐多个传感器的时间戳并处理缺失值。
2. 从最近窗口估计健康度趋势或由时序编码器生成状态向量。
3. 外推状态轨迹并计算穿越安全阈值的时间。
4. 根据区间覆盖率、漂移和风险规则生成建议。

## 框架伪代码

```text
window = history[-W:]
slope = linear_regression(window)
if slope >= 0: return stable
rul = ceil((threshold - last_value) / slope)
return rul, uncertainty_interval
```

## 跟着演示手算

先把噪声调到较低，观察蓝色观测线和黄色预测线的交点；再提高噪声，比较斜率和置信度如何变化。最后移动阈值，确认“剩余时间”改变来自业务阈值，而不是传感器历史被重写。

## 复杂度怎么分析

演示基线使用固定窗口线性回归，时间 O(W)，额外空间 O(W)。Transformer 或 TCN 推理复杂度取决于窗口长度、层数和隐藏维度；训练时还要单独计算滑窗样本和参数量。

## 常见错误

- 用未来窗口计算当前 RUL，造成时间泄露。
- 把暂时尖峰当成不可逆退化。
- 跨设备直接共享阈值，没有校准设备差异。
- 只报告点预测，不报告预测区间、漂移和数据质量。

## 什么时候使用

适合有明确退化过程、可定义安全阈值并且维护成本较高的设备。不适合没有可观测退化信号或失效完全突发的场景；后者应结合异常检测、规则和安全联锁。

## 与其他算法的联系

异常检测用于发现状态偏离，产量预测用于计划层，维护决策用于把 RUL 转为成本约束下的动作。生产升级可选 TCN、Temporal Fusion Transformer、PatchTST 和带检索的维护助手。
