# 维护决策优化 Maintenance Decision

> 已经知道设备有多大概率会故障，下一步是马上停机维修，还是继续生产？这个演示把预测转换为成本敏感的动作选择。

## 先抓住一个问题

故障概率不是动作。模型说“未来一个窗口内有 22% 的概率故障”，并不能直接推出“必须停机”。动作还受到停机损失、维修成本、紧急抢修惩罚、降载造成的产量损失以及安全规则的共同影响。维护决策要回答的是：**在允许的动作集合中，哪个动作的期望代价最低？**

页面提供三个动作：

- **立即维护**：现在安排计划检修，支付维修成本，并承担计划停机的一部分损失。
- **继续运行**：保持当前产能；若故障发生，承担停机损失和紧急维修惩罚。
- **降载运行**：以较低负荷继续生产，先支付降载成本，同时降低故障造成的冲击。这里用 45% 表示降载后仍保留的故障冲击，真实工艺应通过数据校准。

## 期望成本模型

设故障概率为 `p`，停机损失为 `D`，维修成本为 `R`，紧急维修惩罚为 `E`，降载成本为 `L`。演示使用固定的计划停机比例 `α = 0.25` 和降载冲击比例 `β = 0.45`：

```text
cost(immediate) = R + α × D
cost(continue)  = p × (D + E)
cost(derated)   = L + β × p × (D + E)
```

这不是把所有经营因素都压缩成一个“神奇分数”，而是明确列出假设，便于审计和替换。调整滑块后，页面会重新排序三个动作并标出最低成本柱子。

### 为什么要看第二低成本

只显示最优动作会隐藏决策的脆弱程度。例如立即维护是 50 万元、降载是 50.2 万元时，推荐虽然相同，但微小的概率或成本误差就可能改变结论。因此页面同时显示“相对节省”，用最低成本与第二低成本的差值衡量动作间隔。生产系统还应输出置信区间和敏感性分析，而不是只返回一个标签。

## 算法步骤

1. 校验概率在 `[0, 1]`，所有成本非负。
2. 将停机损失和紧急惩罚合并为一次故障事件成本。
3. 对每个动作应用其成本公式，得到三个期望值。
4. 取期望成本最小的动作作为候选推荐。
5. 交给安全规则、设备状态和人工审批做最终裁决。

核心不变量是：**每个动作的成本都使用同一时间窗口、同一货币单位和同一故障概率**。如果某个动作使用“每班”成本而另一个使用“每小时”成本，排序结果就没有意义。

## 复杂度

动作数量固定为 3，计算时间 `O(1)`，额外空间 `O(1)`。工业大模型的成本通常不在这一步，而在前面的多变量时序编码、概率校准和场景模拟；决策层保持小而透明，便于审计和回滚。

## 常见错误

- **把概率当成确定故障**：概率是风险权重，不能绕过安全联锁。
- **遗漏机会成本**：只填维修价格而不填停机和交付损失，会系统性偏向“继续运行”。
- **混淆降载与维修**：降载仍然有残余风险，不能把故障概率直接设为零。
- **用同一成本表覆盖所有设备**：产线、班次、产品和合同罚则不同，成本需要分层校准。
- **没有动作回放**：应该记录当时使用的概率、成本、模型版本、规则版本和最终人工决定。

## 从透明基线升级

生产级系统可以由 TCN、Temporal Fusion Transformer 或时序基础模型从传感器、工艺参数、库存和工单中预测 `p` 的分布，而不是一个点值。决策层可以进一步加入：

1. **区间概率**：对不同置信水平计算最坏情形成本，减少低概率高损失事件的漏防。
2. **约束优化**：将安全阈值、最大连续运行时长和备件库存作为硬约束，而不是成本项。
3. **多步策略**：用有限时域 MDP 或模型预测控制，比较“现在降载、下个班次维护”等序列动作。
4. **人机协同**：系统给出证据和敏感性，工程师确认后才写入工单；出现数据漂移时自动降级到规则流程。
