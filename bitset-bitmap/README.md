# 位集与位图 Bitset / Bitmap

> 用机器字的单个位表达布尔状态并执行批量位运算

## 先抓住一句话

**位集与位图 Bitset / Bitmap** 把有界整数域中的每个值映射到一个二进制位，用紧凑存储支持成员测试和按机器字并行的集合运算。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

用布尔对象或哈希节点保存每个状态会产生显著额外空间。位图让一个 w 位机器字同时承载 w 个布尔值，交、并、异或也可整字执行。

它依赖值到非负整数位置的稳定映射，不处理哈希冲突。

## 心智模型

对于值 x，`x / w` 找到机器字，`x mod w` 找到该字中的位。设置、清除和查询都只是掩码运算。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 第 x 位为 1 当且仅当整数 x 属于集合；所有位运算都保持同一套值域大小、字宽和位序约定。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **位集与位图 Bitset / Bitmap** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 检查 x 是否位于合法值域，计算字索引和位偏移。
2. 用 `word |= 1 << offset` 设置成员位。
3. 用与掩码测试成员，用反掩码清除成员位。
4. 对等长位图逐字执行 AND、OR、XOR 或差集，并用 popcount 统计元素数。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
word_index = x / WORD_BITS
bit_mask = 1 << (x mod WORD_BITS)

add(x):      words[word_index] |= bit_mask
remove(x):   words[word_index] &= ~bit_mask
contains(x): return (words[word_index] & bit_mask) != 0

intersection[i] = left[i] & right[i]
```

把伪代码映射到本目录的 `app.js` 时，可以按“解析输入 → 初始化状态 → 生成每一步 → 更新指标 → Canvas 绘制”的顺序阅读。算法逻辑负责决定状态，绘图逻辑只负责把状态呈现出来，两者不要混在一起理解。

## 复杂度怎么分析

**结论：单点操作 O(1)，批量集合操作 O(n / word size)**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 忽略负数、越界值或最后一个机器字中的无效高位。
- 使用有符号移位或错误字宽，使最高位掩码产生意外结果。
- 对两个值域、位序或长度不同的位图直接执行集合运算。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：稠密有界整数集合、权限标记、筛法、状态压缩和大规模布尔统计。

不适合：巨大而稀疏的值域或任意对象键；集合或压缩位图通常更节省空间。
