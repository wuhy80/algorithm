# 有向图环检测 Directed Cycle Detection

> 用白灰黑三色状态识别 DFS 递归栈中的返祖边

## 先抓住一句话

**有向图环检测 Directed Cycle Detection** 属于 DFS 状态分类问题。它的核心任务是：判断有向依赖中是否存在回到当前搜索路径的边。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

普通的“是否访问过”只能防止重复搜索，不能区分边指向已完成顶点还是当前递归路径中的顶点。三色状态正是为了识别这个差别。

灰色顶点仍位于当前 DFS 路径上，因而一条指向灰色顶点的边会与路径上的树边闭合成有向环。黑色顶点已经完成，其后继也已检查完，指向它的边不会回到当前路径，不能据此判环。

## 心智模型

白色表示尚未进入，灰色表示仍在当前 DFS 调用栈中，黑色表示已经完成。只有指向灰色顶点的边才是证明有向环存在的返祖边。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 灰色顶点恰好构成当前递归路径；遇到 `u -> v` 且 `v` 为灰色时，从 `v` 到 `u` 的树路径与该边组成有向环。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **有向图环检测 Directed Cycle Detection** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 把所有顶点初始化为白色。
2. 进入顶点时标成灰色，并逐条检查它的出边。
3. 递归访问白色邻点；若邻点为灰色，立即报告有向环。
4. 所有出边处理完后把顶点标成黑色，并从每个仍为白色的顶点继续搜索。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

```text
has_cycle(u):
    color[u] = GRAY
    for v in graph[u]:
        if color[v] == GRAY:
            return true
        if color[v] == WHITE and has_cycle(v):
            return true
    color[u] = BLACK
    return false
```

## 复杂度怎么分析

**结论：时间 O(V+E)，空间 O(V)**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 把任何指向“已访问”顶点的边都判成环，误把指向黑色顶点的横叉边算作返祖边。
- 只从一个入度为零的顶点启动 DFS，漏掉不连通子图中的环。
- DFS 返回时忘记把灰色改成黑色，导致后续搜索产生假阳性。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：静态有向图中的依赖环检测、课程或任务调度前置检查，以及需要恢复一条具体环的场景。

不适合：无向图环检测或频繁增删边后的在线判定；无向图需要区分父边，动态图需要专门的数据结构。

## 实现判定细节

- 三色标记中，白色表示未访问，灰色表示仍在当前递归路径，黑色表示该节点的全部后继已经检查完。
- 只有指向灰色节点的边是返祖边并证明有环；指向黑色节点的交叉边不能作为有环依据。
- 递归返回前必须把节点从灰色改成黑色，显式栈实现则要保存“下一个待检查邻居”的位置。
- 若只需要判断 DAG，也可用 Kahn 算法：最终弹出的节点数少于总节点数时，剩余节点处于一个或多个有向环影响范围内。
