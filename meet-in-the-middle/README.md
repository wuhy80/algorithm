# 折半搜索 Meet-in-the-Middle

> 把指数枚举拆成两半并组合两侧结果

## 先抓住一句话

**折半搜索 Meet-in-the-Middle** 属于指数搜索空间分解技巧。它把候选分成两半独立枚举，再组合两侧结果，把 O(2^n) 降为约 O(2^(n/2))。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

直接枚举 n 个元素的全部子集很快不可行。若目标可以由左右两半的摘要组合，就能用额外空间换取指数规模的平方根级下降。

关键不是随机性，而是组合可分：每个完整候选都唯一对应一个左半候选和一个右半候选。

## 心智模型

把所有左半结果存入表中，对每个右半结果寻找能与它组成目标的左半结果；排序、二分或哈希负责高效配对。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 左右两侧分别完整枚举各自选择；二者的笛卡尔积与原问题的全部完整选择一一对应，不重不漏。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **折半搜索 Meet-in-the-Middle** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 把 n 个候选拆成规模接近的左右两半。
2. 枚举左半所有子集摘要并排序或建立哈希表。
3. 枚举右半所有子集摘要，计算所需的互补摘要。
4. 通过二分、双指针或哈希查找配对，并恢复答案。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 复杂度怎么分析

**结论：时间和空间通常为 O(2^(n/2))**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 两半规模严重失衡，导致较大一侧仍接近 O(2^n)。
- 只保存摘要值却在题目要求方案时没有保留对应子集。
- 组合时重复计入边界元素，或错误处理重复摘要和计数。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：n 约为 30 到 50、完整搜索为 2^n，且目标能分解为两半摘要组合的问题。

不适合：状态无法独立拆分，或 O(2^(n/2)) 的时间和空间仍超过限制的场景。

## 实现判定细节

- 把 n 个选择拆成两半，各自枚举约 `2^(n/2)` 个状态，再通过排序、哈希或双指针组合两侧结果。
- 子集和判定中，左侧和为 `x` 时只需在右侧查找 `target-x`；求最优值时则查找不超过剩余额度的边界。
- 若输入含负数，双指针和剪枝条件不能沿用“和只会增大”的假设，但排序后二分仍然有效。
- 真正的收益来自指数减半，代价是保存半边状态的内存；n 很大但状态值域小时，普通 DP 可能更合适。
