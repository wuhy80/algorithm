# Li Chao Tree

> 在线维护直线集合并查询指定横坐标的最优值

## 先抓住一句话

**Li Chao Tree** 在固定横坐标域上动态插入直线，并以对数复杂度查询指定 x 处的最小值；斜率和查询顺序都不要求单调。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

每次查询遍历全部直线需要 O(number of lines)。Li Chao Tree 利用两条直线至多相交一次，把可能胜出的区间限制到至多一侧。

本演示查询最小值，并预先离散化所有查询横坐标；最大值版本需要统一反转比较，不能只改查询处的 `min`。

## 心智模型

每个节点保存一条在区间中点更优的直线。中点较差的直线只有在某个端点更优时，才可能进入对应子区间继续竞争。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 节点保留到达该区间的直线中在中点最优者；被继续下放的直线只可能在一个子区间胜出，查询根到叶路径即可覆盖所有候选。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **Li Chao Tree** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 在当前区间中点比较新线与节点原有直线，让中点更优者留在节点。
2. 若新线在左端比保留线更优，把它递归插入左子区间。
3. 否则若新线在右端更优，把它递归插入右子区间；两端都不优则丢弃。
4. 查询 x 时沿对应根到叶路径，计算并取路径上所有存储直线的最小值。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
insert(new_line, node, left, right):
    mid = (left + right) / 2
    if new_line(x[mid]) < node.line(x[mid]):
        swap(new_line, node.line)
    if left == right: return
    if new_line(x[left]) < node.line(x[left]):
        insert(new_line, node.left, left, mid)
    else if new_line(x[right]) < node.line(x[right]):
        insert(new_line, node.right, mid + 1, right)

query(x_index):
    return minimum line value along root-to-leaf path
```

把伪代码映射到本目录的 `app.js` 时，可以按“解析输入 → 初始化状态 → 生成每一步 → 更新指标 → Canvas 绘制”的顺序阅读。算法逻辑负责决定状态，绘图逻辑只负责把状态呈现出来，两者不要混在一起理解。

## 复杂度怎么分析

**结论：插入和查询 O(log coordinate range)**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 中点交换后仍按交换前的两条线判断端点，递归方向错误。
- 最小值版和最大值版的比较符号混用，或平行线没有保留截距更优者。
- `m*x+b` 使用的数值类型溢出，或查询了未包含在离散坐标域中的 x。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：直线动态加入、斜率和查询点无单调性，且需要在线最值查询的 DP 优化。

不适合：函数不是直线、定义域持续扩张却没有动态节点设计，或直线只在部分区间有效而实现不支持线段插入。
