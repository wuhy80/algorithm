# 割点与桥

> DFS 树回溯、Lowlink 更新及关键节点与边判定

## 先抓住一句话

**割点与桥** 用一次 DFS 找出无向图中的关键连接：删除桥会增加连通分量数，删除割点及其关联边也会增加连通分量数。核心不是模拟删除，而是判断一棵 DFS 子树能否绕过父边回到祖先。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

逐一删除每条边、每个顶点再做连通性检查，需要反复遍历整张图。Lowlink 把“子树能到达的最早祖先”压缩成一个数，使每条边只处理常数次便能同时判定所有桥和割点。

## 心智模型

`dfn[u]` 是顶点 `u` 首次进入 DFS 的时间；`low[u]` 是从 `u` 的 DFS 子树出发，经若干树边并至多使用一条返祖边能够到达的最小 `dfn`。对树边 `u-v`，若 `v` 的子树无法绕到 `u` 之前，`u-v` 就是必经连接。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 从子节点 `v` 回溯到 `u` 时，`low[v]` 已完整概括 `v` 的整棵子树。于是 `low[v] > dfn[u]` 判定桥，非根节点的 `low[v] >= dfn[u]` 判定割点；DFS 根节点则只看独立 DFS 孩子数是否至少为 2。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **割点与桥** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 从每个未访问顶点启动 DFS，进入 `u` 时令 `dfn[u] = low[u] = ++time`。
2. 遇到未访问邻居 `v`，把边作为树边递归处理；回溯后令 `low[u] = min(low[u], low[v])`。
3. 遇到已访问邻居时，只跳过本次进入 `u` 的父边，并用 `dfn[v]` 更新 `low[u]`。
4. 对树边应用桥与割点判定式；对 DFS 根节点单独统计树孩子数量。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
dfs(u, parent_edge):
    dfn[u] = low[u] = ++time
    child_count = 0
    for (v, edge_id) in graph[u]:
        if edge_id == parent_edge: continue
        if dfn[v] == 0:
            child_count += 1
            dfs(v, edge_id)
            low[u] = min(low[u], low[v])
            if low[v] > dfn[u]: mark edge (u, v) as bridge
            if parent_edge exists and low[v] >= dfn[u]: mark u as articulation
        else:
            low[u] = min(low[u], dfn[v])
    if parent_edge does not exist and child_count >= 2:
        mark u as articulation
```

把伪代码映射到本目录的 `app.js` 时，可以按“解析输入 → 初始化状态 → 生成每一步 → 更新指标 → Canvas 绘制”的顺序阅读。算法逻辑负责决定状态，绘图逻辑只负责把状态呈现出来，两者不要混在一起理解。

## 复杂度怎么分析

**结论：一次 Tarjan DFS，时间 O(V+E)，空间 O(V)。邻接表实现中，每个顶点和每条边只处理常数次。**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 无向图按“父节点”而不是边编号跳过父边，导致平行边被错误忽略。
- 处理返祖边时使用 `low[v]`，把不属于当前 DFS 子树的信息错误传播进来；此处应使用 `dfn[v]`。
- 用 `low[v] >= dfn[u]` 判断桥；桥必须是严格大于，等号只说明子树能回到 `u`。
- 忘记 DFS 根节点的割点判定与非根节点不同，或把图默认成连通图而漏掉后续分量。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：静态无向图中的网络脆弱性分析、桥和割点查询，以及双连通分量分解的前置计算。

不适合：有向图的强连通分量，或边和顶点频繁增删且需要在线回答的动态连通性问题。

## 自测问题

- 为什么桥使用 `low[v] > dfn[u]`，而非根割点使用 `low[v] >= dfn[u]`？
- 两个顶点之间有两条平行边时，为什么按父节点跳过边会误判出桥？
- 把演示输入缩小到 3 到 6 个元素，能否在纸上预测下一帧再点击“单步”？
- 当前复杂度的主导项来自哪里？换一种底层数据结构后会怎样变化？

## 实现判定细节

- 无向边必须携带唯一边编号；DFS 只跳过进入当前节点的那条父边，不能按父节点编号跳过，否则平行边会被误判。
- 对树边 `u-v`，`low[v] > dfn[u]` 才说明它是桥；等号表示子树仍能回到 `u`，但到不了 `u` 的祖先。
- 非根节点存在孩子满足 `low[v] >= dfn[u]` 时是割点；DFS 根节点必须单独按“至少两个 DFS 孩子”判断。
- 断开图要从每个未访问节点重新启动 DFS，时间戳可以连续递增，但根节点和父边状态必须重新初始化。
