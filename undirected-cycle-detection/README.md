# 无向图环检测 Undirected Cycle Detection

> 在 DFS 中区分父边与已访问邻居并标出成环边

## 先抓住一句话

**无向图环检测 Undirected Cycle Detection** 属于基础 DFS 问题。它的核心任务是：在无向图中区分“沿原边返回父节点”和真正连接到已访问顶点的非树边。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

无向边会在邻接表中出现两次，因此子节点总能看到通向父节点的边。若不排除这条父边，任何一条普通边都会被误判为环。

排除进入当前顶点的那条父边后，若仍存在通向已访问顶点的边，这条边就与 DFS 树中的唯一路径闭合成环。按边编号而非父节点排除尤其重要，否则两个顶点间的平行边会被一起跳过。

## 心智模型

DFS 走过的边构成一棵森林。检查一条边时，若另一端已经访问且这条边不是进入当前顶点的同一条父边，就找到了闭合路径。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 每条无向边按边编号处理；遇到已访问邻点时，只有当前边编号不等于父边编号才说明存在环。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **无向图环检测 Undirected Cycle Detection** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 为每条无向边分配唯一编号，并把它加入两个端点的邻接表。
2. 从每个未访问顶点启动 DFS，同时传入进入当前顶点的父边编号。
3. 对未访问邻点递归搜索；对已访问邻点检查它是否来自另一条边。
4. 找到非父边的已访问邻点时报告环，否则完成整张图后报告无环。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
has_cycle(u, parent_edge):
    visited[u] = true
    for (v, edge_id) in graph[u]:
        if edge_id == parent_edge:
            continue
        if visited[v]:
            return true
        if has_cycle(v, edge_id):
            return true
    return false
```

## 复杂度怎么分析

**结论：时间 O(V+E)，空间 O(V)**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 只按父顶点而不是父边编号跳过边，无法正确处理平行边构成的长度为 2 的环。
- 没有跳过父边，导致任意非空森林都被判为有环。
- 只从一个顶点搜索，漏掉其他连通分量中的环。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：静态无向图的成环判定、冗余连接检查，以及构造生成森林前的合法性验证。

不适合：有向图或频繁在线加边、删边的图；有向图应使用三色 DFS，只有增边时也可考虑并查集。

## 实现判定细节

- DFS 中遇到已访问邻居不一定有环：指向进入当前节点的父边必须跳过，但同一父节点之间的第二条平行边仍然构成长度为 2 的环。
- 因此可靠实现应按边编号跳过父边，而不是简单判断 `neighbor == parent`。
- 并查集版本按边扫描：若一条边的两个端点在加入前已经同属一个集合，这条边闭合了一个环；随后再执行合并。
- 自环立即构成环，断开图则需要从所有未访问节点启动 DFS 或让并查集扫描全部边。
