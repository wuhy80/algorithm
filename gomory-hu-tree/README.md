# Gomory-Hu 全局割树

> 执行 V-1 次最小割并调整父关系，用一棵树编码全部点对最小割。

## 先抓住一句话

**Gomory-Hu 全局割树** 属于无向图的所有点对最小割结构。它只做 `V-1` 次最大流，就用一棵带权树编码任意两点间的最小割值。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

直接对每一对顶点求最小割需要 O(V²) 次最大流。Gomory-Hu 利用无向割的层次关系复用每次最小割得到的划分，把调用次数降为 `V-1`。

每轮最小割不仅给出一个数，还给出源点所在的割侧。这个划分决定哪些待处理顶点应改挂到当前源点；父关系调整正确，最终树上的路径最小边权才能同时回答所有点对查询。

## 心智模型

先让每个非根顶点指向一个候选父节点。对顶点 `s` 与其父 `t` 求最小割后，用残量网络中的可达侧调整其他父关系，并把割值写到树边上。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 构造完成后，原图中任意两点 `u, v` 的最小割值，等于割树上 `u-v` 唯一路径中的最小边权。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **Gomory-Hu 全局割树** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 选择顶点 0 为根，初始化所有其他顶点的父节点为 0。
2. 依次对 `s` 和当前 `parent[s]` 求最小割，同时取得残量网络中源点可达集合。
3. 将同父且与 `s` 位于割同侧的后续顶点改挂到 `s`，必要时交换父子关系与旧割值。
4. 把本次割值记录到对应树边；完成 `V-1` 轮后输出割树。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
parent[1..V-1] = 0
for s = 1 .. V-1:
    t = parent[s]
    (cut_value[s], source_side) = min_cut(s, t)
    for i > s:
        if parent[i] == t and i in source_side:
            parent[i] = s
    adjust parent relation if parent[t] is in source_side
return edges (s, parent[s], cut_value[s])
```

把伪代码映射到本目录的 `app.js` 时，可以按“解析输入 → 初始化状态 → 生成每一步 → 更新指标 → Canvas 绘制”的顺序阅读。算法逻辑负责决定状态，绘图逻辑只负责把状态呈现出来，两者不要混在一起理解。

## 复杂度怎么分析

**结论：V-1 次最大流**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 把算法用于有向图；割树依赖无向图最小割的特殊结构。
- 每次最大流复用上一次被修改的残量容量，而不是从原始容量重新建立残量网络。
- 只记录割值，不根据源侧可达集合调整父关系，最终树无法编码其他点对的最小割。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：静态无向非负带权图中需要大量任意点对最小割查询，或需要一个紧凑的割等价表示。

不适合：有向图、只查询一对点、需要列举所有不同最小割划分，或无法承担 `V-1` 次最大流的超大图。

## 实现判定细节

- Gomory-Hu 树只适用于无向带非负容量图；树上任意两点路径的最小边权等于原图两点间最小割值。
- 第 `s` 轮只需计算 `s` 与当前父节点 `t` 的一次最大流，并用残量图中从 `s` 可达的集合批量调整后续父指针。
- 若 `parent[t]` 也位于 `s` 侧，需要执行父子交换并同步割值，否则树结构虽连通但不能保持最小割语义。
- 每次最大流前必须从原始容量重新构造残量网络，不能复用上一轮已经消耗的容量。
