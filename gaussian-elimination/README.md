# 高斯消元 Gaussian Elimination

> 通过部分选主元、行归一化和逐列消元得到行最简形与唯一解。

## 先抓住一句话

**高斯消元 Gaussian Elimination** 通过不改变方程组解集的初等行变换，把增广矩阵化为阶梯形或行最简形，从而求解未知量并判断秩。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

把方程逐个代入会迅速变得混乱。矩阵行变换统一执行交换、倍乘和行加法，并逐列建立主元。

演示采用部分选主元的 Gauss-Jordan 消元：选绝对值最大的候选主元，归一化后同时消去该列的上方与下方元素；当前页面只输出方阵的唯一解。

## 心智模型

每个主元锁定一个独立变量方向。完成一列后，该主元列成为单位向量，后续行变换不能破坏已完成的主元列。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 每次初等行变换前后方程组解集相同；已处理主元列在各自主元行为 1、其余行为 0。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **高斯消元 Gaussian Elimination** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 从当前行开始，在本列寻找绝对值最大的非零主元并交换到当前行。
2. 用主元除整行，使主元归一化为 1。
3. 对其他所有行减去适当倍数的主元行，把该列其余元素消为 0。
4. 移到下一行与下一列；根据主元数和矛盾行判断唯一解、无解或无穷多解。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
row = 0
for col in 0 .. variables - 1:
    pivot = argmax(abs(A[r][col])) for r >= row
    if abs(A[pivot][col]) < epsilon: continue
    swap(A[pivot], A[row])
    A[row] /= A[row][col]
    for r in 0 .. rows - 1:
        if r != row:
            A[r] -= A[r][col] * A[row]
    row += 1
classify_solution(A, pivot_count=row)
```

把伪代码映射到本目录的 `app.js` 时，可以按“解析输入 → 初始化状态 → 生成每一步 → 更新指标 → Canvas 绘制”的顺序阅读。算法逻辑负责决定状态，绘图逻辑只负责把状态呈现出来，两者不要混在一起理解。

## 复杂度怎么分析

**结论：O(n³)**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 固定使用对角元素作主元，遇到零或很小的值时除零并放大误差。
- 只更新系数列，没有对增广列执行完全相同的行变换。
- 用精确等于零判断浮点主元，或把主元不足直接都判成无解。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：中小规模稠密线性方程组、秩与逆矩阵计算；本演示聚焦唯一解。

不适合：大型稀疏系统或病态矩阵；应使用稀疏迭代法、QR/SVD 等更合适且数值稳定的工具。
