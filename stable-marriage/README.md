# 稳定婚姻匹配 Gale-Shapley

> 自由提议者依偏好提议，接收者始终保留当前更偏好的匹配。

## 先抓住一句话

**稳定婚姻匹配 Gale-Shapley** 属于偏好匹配算法。它通过反复提议得到不存在阻塞对的稳定匹配，而不是求最大匹配或最小费用匹配。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

仅保证每人匹配一次并不能保证稳定：仍可能存在彼此都更偏好对方的阻塞对。Gale-Shapley 用单调提议过程排除这种情况。

提议者不会重复向同一人提议；接收者只会把暂定对象换成更偏好的对象，因此双方状态都单调推进。

## 心智模型

每个自由提议者按偏好顺序向尚未尝试的人提议。接收者比较当前暂定对象与新提议者，只保留更偏好的一个。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 接收者的暂定对象只会越来越符合其偏好；提议者被拒绝后，不可能与该接收者形成最终阻塞对。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **稳定婚姻匹配 Gale-Shapley** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 将所有提议者放入自由队列，并记录其下一个偏好位置。
2. 取出一名自由提议者，向尚未尝试的最高偏好接收者提议。
3. 若对方自由则暂定匹配；否则保留更偏好的提议者，并让被替换者重新自由。
4. 重复直到没有自由且仍可提议的人。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
free = queue(all proposers)
while free not empty:
    p = free.pop()
    r = next_unproposed_choice(p)
    if r has no partner:
        engage(p, r)
    else if r prefers p over current_partner[r]:
        free.push(current_partner[r])
        engage(p, r)
    else:
        free.push(p)
return engagements
```

把伪代码映射到本目录的 `app.js` 时，可以按“解析输入 → 初始化状态 → 生成每一步 → 更新指标 → Canvas 绘制”的顺序阅读。算法逻辑负责决定状态，绘图逻辑只负责把状态呈现出来，两者不要混在一起理解。

## 复杂度怎么分析

**结论：O(n²)**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 没有记录每名提议者已尝试到偏好表的哪个位置，导致重复提议。
- 替换暂定对象时忘记把旧对象重新放回自由队列。
- 把稳定性等同于总偏好最优；结果只保证无阻塞对，并偏向提议方。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：两侧参与者都有严格偏好序，目标是消除阻塞对的稳定一一匹配。

不适合：目标是最大匹配、最小总成本、多容量分配，或偏好包含复杂外部约束的场景。

## 实现判定细节

- Gale-Shapley 中每个提议者按偏好顺序最多向每个接收者提议一次，因此总提议次数不超过 n²。
- 接收者暂时保留自己更偏好的提议者，被拒绝者重新进入队列；已经拒绝过的人不应再次提议。
- 接收者偏好表应预处理为排名数组，使比较两个候选是 O(1)，否则实现会额外退化一阶。
- 结果对提议方最优、对接收方最差，但稳定不等于总满意度最大；稳定性检查要寻找双方都更偏好的阻塞对。
