# 差分数组 Difference Array

> 区间更新只修改两个差分边界，最后通过前缀累加恢复完整数组。

## 先抓住一句话

**差分数组 Difference Array** 保存相邻元素的变化量，让一次闭区间加法只修改起点和终点后一位，最后用一次前缀累加恢复结果。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

直接给 `A[l..r]` 的每个元素加 delta，每次要修改 O(r-l+1) 项。差分数组只记录“从哪里开始增加”和“从哪里停止增加”。

它把大量更新集中后一次性物化，适合离线批处理；若更新之间必须立即回答任意区间查询，需要 Fenwick Tree 或线段树。

## 心智模型

`diff[i]` 是当前位置相对前一位置的增量。给 `[l,r]` 加 delta，相当于从 l 开始把累计值提高 delta，并在 r+1 恢复。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 对任意 i，`diff[0]+...+diff[i]` 等于应用当前全部区间更新后的 `A[i]`；两个边界修改恰好让 delta 只在目标区间内持续生效。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **差分数组 Difference Array** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 建立 `diff[0]=A[0]`，其余位置为 `A[i]-A[i-1]`。
2. 对闭区间更新 `[l,r]+=delta`，执行 `diff[l]+=delta`。
3. 若 `r+1<n`，再执行 `diff[r+1]-=delta` 终止影响。
4. 所有更新完成后，从左到右对 diff 求前缀和得到最终数组。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
diff[0] = array[0]
for i in 1 .. n - 1:
    diff[i] = array[i] - array[i - 1]

range_add(left, right, delta):
    diff[left] += delta
    if right + 1 < n:
        diff[right + 1] -= delta

running = 0
for i in 0 .. n - 1:
    running += diff[i]
    result[i] = running
```

把伪代码映射到本目录的 `app.js` 时，可以按“解析输入 → 初始化状态 → 生成每一步 → 更新指标 → Canvas 绘制”的顺序阅读。算法逻辑负责决定状态，绘图逻辑只负责把状态呈现出来，两者不要混在一起理解。

## 复杂度怎么分析

**结论：O(1) 更新 / O(n) 恢复**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 闭区间更新在 `diff[right]` 而不是 `diff[right+1]` 处抵消。
- 建表时忘记 `diff[0]=A[0]`，恢复后整体偏移。
- 每次更新后立即完整恢复数组，重新退化为 O(n) 更新。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：大量离线区间加法，最后一次性输出每个位置的最终值。

不适合：更新与在线查询交替、需要区间和，或更新不是可叠加的边界变化；应选择树状数组或线段树。
