# Rabin-Karp 字符串匹配

> 文本窗口滑动、滚动哈希更新和哈希碰撞校验

## 先抓住一句话

**Rabin-Karp 字符串匹配** 用滚动哈希快速筛选与模式等长的文本窗口，并对哈希相等的候选做逐字符校验。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

逐字符检查每个窗口会重复计算大量相邻字符。滚动哈希在 O(1) 时间从当前窗口指纹更新到下一个窗口指纹。

哈希相等只表示“可能匹配”。为了保证确定性正确，仍要比较原始字符排除碰撞。

## 心智模型

把长度为 m 的窗口看作 base 进制数。滑动时减去最高位字符、整体乘 base，再加入新字符。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 扫描起点 i 时，窗口哈希严格对应 `text[i:i+m]`；只有哈希与模式相等且原文校验通过时才报告匹配。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **Rabin-Karp 字符串匹配** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 计算模式哈希、首个文本窗口哈希和最高位权重 `base^(m-1)`。
2. 若当前窗口哈希等于模式哈希，逐字符校验并记录真实匹配。
3. 移除窗口左端字符对哈希的贡献。
4. 乘 base 并加入新字符，在模数下规范化后继续滑动。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
pattern_hash = hash(pattern)
window_hash = hash(text[0:m])
high = base^(m - 1) mod modulus
for i in 0 .. n - m:
    if window_hash == pattern_hash and text[i:i+m] == pattern:
        emit(i)
    if i < n - m:
        window_hash -= code(text[i]) * high
        window_hash = window_hash * base + code(text[i + m])
        window_hash = normalize(window_hash, modulus)
```

把伪代码映射到本目录的 `app.js` 时，可以按“解析输入 → 初始化状态 → 生成每一步 → 更新指标 → Canvas 绘制”的顺序阅读。算法逻辑负责决定状态，绘图逻辑只负责把状态呈现出来，两者不要混在一起理解。

## 跟着演示手算

1. 打开页面后先暂停，抄下初始输入，并写出你认为最重要的状态变量。
2. 点击一次“单步”前，先根据不变量预测哪些值、节点、边或区间会改变。
3. 对照状态栏观察“文本窗口滑动、滚动哈希更新和哈希碰撞校验”是否正在发生，并解释为什么没有选择其他候选。
4. 到达终态后只改一个边界条件，例如空输入、重复值、极端顺序、断开的图或最小规模，再重新运行。
5. 最后尝试不看动画，只根据伪代码复现同一过程；能独立写出状态变化才算真正掌握。

## 复杂度怎么分析

**结论：平均 O(n+m)，哈希碰撞频繁时最坏 O(nm)；空间 O(1) 或 O(m)。**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 更新窗口时使用了错误的最高位幂或字符索引。
- 取模后保留负值，导致相同窗口得到不同表示。
- 把哈希相等直接当作匹配，不做原文校验或双哈希防护。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：同时搜索多个等长模式、二维匹配，或已有滚动哈希基础设施的场景。

不适合：对抗性输入下又不能容忍碰撞和最坏 O(nm) 校验成本；可改用 KMP 等确定性线性算法。
