# 离线动态连通性 Offline Dynamic Connectivity

> 时间线段树配合可回滚并查集处理边的增删与查询

## 先抓住一句话

**离线动态连通性 Offline Dynamic Connectivity** 属于时间分治问题。它把边的有效时间段放入线段树，并用可回滚并查集回答每个时刻的连通性。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

普通并查集不支持删边。离线读取全部操作后，可以把每条边从加入到删除的时间变成区间，再让线段树把“删除”改写为进入和退出时间区间时的合并与回滚。

每条边的有效期被拆到 O(log q) 个互不重叠的线段树节点。沿根到某个查询时刻的路径收集这些节点，得到的边集合恰好等于该时刻的活动边；离开节点时回滚，便不会把当前时间段的边泄漏到兄弟分支。

## 心智模型

线段树节点代表一段时间。只要一条边在整段时间内始终存在，就把它存到该节点；DFS 到叶子时，并查集恰好包含该时刻所有有效边。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 进入时间线段树节点后，并查集包含从根到该节点路径上保存的全部边；离开节点并回滚后，状态与进入前完全相同。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **离线动态连通性 Offline Dynamic Connectivity** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 扫描操作序列，把每条边的 `add` 到 `remove` 配对成半开有效区间 `[start, end)`。
2. 将每个有效区间分解并加入时间线段树的 O(log Q) 个节点。
3. DFS 进入节点时保存快照，并合并该节点存放的全部边。
4. 到叶子时回答查询；离开节点前回滚到快照，再处理其他时间分支。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
for each edge lifetime [l, r):
    add edge to segment_tree interval [l, r)

solve(node, l, r):
    snap = dsu.snapshot()
    for edge in node.edges: dsu.union(edge.u, edge.v)
    if r - l == 1:
        answer query at time l
    else:
        solve(left child); solve(right child)
    dsu.rollback(snap)
```

## 复杂度怎么分析

**结论：约 O((Q + K) log Q log V)**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 把边的删除时刻包含在有效区间内，造成 `[start, end)` 边界错误。
- 同一条边可能重复加入时仍只用一个起始时间，需要计数或栈来区分多重生命周期。
- 访问完线段树子树后没有回滚，导致其他时间区间继承不应存在的边。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：全部操作可以预先获得，且操作由无向边的加入、删除和两点连通性查询组成。

不适合：查询必须在操作到达时立即回答的真正在线场景，或需要维护路径、桥、最短路等比连通性更丰富的信息。

## 实现判定细节

- 先把每条边从加入到删除的有效时间转成半开区间 `[start,end)`，仍未删除的边延伸到操作序列末尾。
- 把边区间加入时间线段树覆盖的 O(log q) 个节点；DFS 到某个节点时合并该节点的全部边，离开时回滚到进入前快照。
- 回滚并查集不能使用普通路径压缩，因为压缩会产生大量难以撤销的父指针修改；按大小合并可把树高控制在 O(log n)。
- 重复加入、删除不存在的边和无向边端点顺序必须在输入契约中统一，否则边的生命周期会被错误配对。
