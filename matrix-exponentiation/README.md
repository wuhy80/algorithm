# 矩阵快速幂 Matrix Exponentiation

> 按指数二进制位重复平方方阵，并在置位时乘入结果矩阵。

## 先抓住一句话

**矩阵快速幂 Matrix Exponentiation** 把指数写成二进制，利用矩阵乘法的结合律重复平方，在 O(log n) 次矩阵乘法内计算高次幂。

学习时只盯住两件事：**当前状态表示什么**，以及**这一步为什么可以排除其他可能**。演示中的颜色、指针、队列、区间或节点变化，都是这两个问题的可视化表达。

## 为什么需要它

顺序计算 `A^n` 需要 n-1 次矩阵乘法。快速幂把指数减半，每个二进制位最多做一次乘入和一次平方。

矩阵乘法通常不可交换，算法依赖的是结合律；乘入结果时必须保持约定的左右顺序。

## 心智模型

`base` 保存当前二进制位对应的 `A^(2^k)`，`result` 累积已经处理的置位，剩余指数每轮右移一位。

面对新题时，不要先问“该套哪个模板”，先问：

1. 输入中有什么结构可以利用，例如有序性、连续区间、树形依赖、图的边或重复子问题？
2. 当前保存的状态是否足以决定下一步？
3. 哪些候选已经可以被严格证明不可能，因而永远不用再看？

## 核心不变量

> 每轮开始时 `result × base^exponent` 等于原始目标 `A^n`；result 初始为单位矩阵，因此指数为 0 时答案正确。

所谓不变量，就是算法每一步开始和结束时都必须为真的事实。调试 **矩阵快速幂 Matrix Exponentiation** 时，最有效的方法不是盯着最终答案，而是在每次单步后检查这条不变量。只要某一帧不再满足它，错误通常就在上一帧的边界更新、状态转移或数据结构维护中。

## 算法步骤

1. 把结果初始化为同阶单位矩阵，base 初始化为输入矩阵。
2. 若当前指数最低位为 1，令 `result=result×base`。
3. 令 `base=base×base`，指数整除 2。
4. 重复直到指数为 0；需要模运算时每次乘加都及时取模。

演示把这些步骤保存为一系列状态快照。先单步执行，确认自己能预测下一帧，再使用连续播放。若只看动画而不预测，容易记住颜色变化，却没有真正掌握决策依据。

## 框架伪代码

下面的伪代码刻意忽略页面绘制和工程细节，只保留这类算法最值得迁移的骨架：

```text
matrix_power(base, exponent):
    result = identity_matrix(base.size)
    while exponent > 0:
        if exponent is odd:
            result = result * base
        exponent = exponent / 2
        if exponent > 0:
            base = base * base
    return result
```

把伪代码映射到本目录的 `app.js` 时，可以按“解析输入 → 初始化状态 → 生成每一步 → 更新指标 → Canvas 绘制”的顺序阅读。算法逻辑负责决定状态，绘图逻辑只负责把状态呈现出来，两者不要混在一起理解。

## 复杂度怎么分析

**结论：朴素 k 阶矩阵乘法下时间 O(k³ log n)，额外空间 O(k²)。**

不要只背大 O。分析时分三步：先数一共有多少个状态或元素，再数每个状态被处理多少次，最后把排序、堆操作、哈希查询、递归深度或额外表格单独计入。若算法具有摊还或期望复杂度，还要说明“总成本如何分摊”或“随机性假设是什么”。

## 常见错误

- 结果从零矩阵开始，导致所有后续乘积仍为零。
- 把矩阵乘法误当作可交换操作，改变乘入顺序。
- 指数为 0、负指数或整数乘法溢出没有定义和处理。
- 只用默认样例验证，没有测试空结构、单元素、重复值、断开输入或最大边界。
- 把演示中的视觉位置当作算法状态；真正应该验证的是数据、索引、距离、计数或引用关系。

## 什么时候使用

适合：固定线性状态转移重复执行很多次，以及求线性递推的远期项。

不适合：转移随时间变化，或阶数很大且矩阵稀疏；应利用问题的稀疏性、特征多项式或专用递推算法。
